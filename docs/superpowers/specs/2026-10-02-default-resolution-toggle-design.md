# BT 搜索默认清晰度切换（1080p / 2160p）设计

- 日期：2026-10-02
- 状态：设计已获用户批准，待实现
- 涉及文件：`movie.plus.user.js`、`tests/test_search_urls.mjs`

## 背景与目标

BT 英文搜索查询的质量后缀目前写死为 ` 1080p`（电影：`片名 年份 1080p`；剧集：`片名 1080p`）。目标：允许在 1080p / 2160p 之间切换默认清晰度，入口放在豆瓣页面的 BT 搜索面板内，一键切换、立即生效、跨页面持久。

## 功能行为

- 可选值仅两个：`1080p`（默认）与 `2160p`。
- 影响范围：`build_bt_sites` 的英文搜索（电影与剧集两个分支）。
- 不受影响：`BTDigg 中`（纯中文片名搜索）、三个字幕站点。
- 切换后 BT 搜索链接立即按新值重建，无需刷新页面；字幕面板不重建。

## UI 设计

- 位置：BT 搜索面板标题行 `h2`（"BT 搜索 · · · · · ·"）末尾。
- 形态：一个小标签显示当前值（如 `2160p`），弱灰色、hover 高亮，`title="切换默认清晰度"`。
- 交互：点击 → 值在两个选项间切换 → 标签文字更新 → BT 面板 `ul` 清空并按已解析的页面信息重建链接。
- 标签显示的是"当前生效值"，不是"将切换到的值"。

## 持久化

- 存储：豆瓣页面 `localStorage`，key `movieplus:res`，值仅限 `'1080p'` / `'2160p'`。
- 读取：缺失或非法值一律回退 `'1080p'`。
- 降级：`localStorage` 抛异常（隐私模式等）时读失败按缺失处理、写失败静默，偏好仅当次页面有效，功能不报错、不中断。

## 代码结构

沿用现有分层（纯函数构造 URL / DOM 渲染分离）：

- `get_res_pref()` → `'1080p' | '2160p'`：读 localStorage，非法回退。
- `toggle_res_pref()` → 切换后的新值：翻转并写回。
- `build_bt_sites(title, year, title_cn, res)`：新增第 4 参数，缺省 `'1080p'`，保持纯函数。
- BT 链接渲染抽为一个小函数（名称实现时定）：输入页面解析出的 title / year / title_cn 与当前偏好，渲染进 BT 面板 `ul`；`update_bt_site` 相应调整。
- `main()`：渲染完成后绑定标题行标签的 click：切换偏好 → 更新标签文字 → 清空 ul → 重新渲染。
- 版本号：`261002.4`。

## 错误处理

- 页面结构异常（无 `h1` 等）：沿用现有早退逻辑，不渲染面板自然也没有切换入口。
- localStorage 异常：try/catch 包裹，读失败回退 1080p，写失败静默。
- 偏好值在读取处统一归一化为两个合法值之一，任意存储内容都不会被拼进搜索 URL。
